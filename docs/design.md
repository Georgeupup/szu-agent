# 设计说明

> 爱小荔的详细设计、各功能的验证状态和工程取舍。使用和部署见 [README](../README.md)。部分数字（测试数量等）是写作当时的。

用自然语言处理深圳大学的日常事务：**发现校园活动、预约体育场馆、查宿舍电费**，顺带查课表、图书馆和公文通。

```
你：今天有什么课？
  🔧 course_today ✗ LOGIN_REQUIRED
荔园助手：查课表需要先登录深大统一身份认证，请在下面的卡片里扫码。
╭── 登录深大统一身份认证 ──╮
│   [二维码]  企业微信扫一扫 │   ← 密码/扫码都不经过 AI 模型
╰──────────────────────────╯
  ✓ 已登录 → 自动继续
  🔧 course_today ✓
荔园助手：今天只有一节课：马克思主义基本原理，第 7-8 节，致理楼 L1-307。

你：帮我约周日晚 8 点的健身房
  🔧 sports_projects / sports_slots / sports_reserve_preview
╭─── ⚠️ 确认预约 ───╮
│ 校区：粤海校区     │  ← 由图强制弹出，不依赖 LLM 自觉
│ 时段：20:00-21:00  │
╰────────────────────╯
```

完全独立运行：自己实现了深大统一身份认证（扫码 / 账号密码）和各子系统的 HTTP 适配器，不需要安装任何其他程序。

## 快速开始

需要 Python ≥ 3.12 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
cp .env.example .env               # 填写 LLM_API_KEY（任意 OpenAI 兼容接口，如 DeepSeek）

uv run szu-agent-web --mock        # 演示模式：样例数据，扫码会自动“确认”，密码随便填
uv run szu-agent-web               # 真实模式
# 打开 http://127.0.0.1:8000
```

在 Docker 里运行时会自动监听 `0.0.0.0`（容器内的 `127.0.0.1` 外部访问不到），浏览器打开 `http://localhost:8000` 即可。
建议用 `-p 127.0.0.1:8000:8000` 映射端口，只让本机访问：这个页面能使用你的校园登录凭证，不应该暴露给局域网。

界面背景只有天空：颜色随一天的时间连续变化，大团柔和的云像隔着磨砂玻璃看到的一样；天气会让云变多变灰、阳光变弱，下雨时有雨丝。所有面板是毛玻璃。左侧“今日荔园”显示校区天气（Open-Meteo，连不上时退回 wttr.in，缓存 15 分钟）。
预览：`?t=19:30` 固定时刻，`?t=cycle` 60 秒快进一整天，`?w=rain` / `?w=overcast` / `?w=clear` 模拟天气。
文字可读性是算出来的：玻璃上的正文全天（含阴雨）对比度 ≥ 6.9；直接写在天空上的时钟和天气按“天空 + 可能飘过的云”选字色并配一层柔和光晕，最差 ≥ 5.6。

第一次用到需要登录的功能时，聊天里会弹出登录卡片；登录后助手自动接着完成刚才的任务。
勾选“7 天内免登录”时学校给 7 天有效期，期间所有任务自动复用凭证。

终端版：

```bash
uv run szu-agent login             # 扫码登录（二维码会用系统图片查看器打开）
uv run szu-agent login --password  # 账号密码登录（getpass 输入，不回显）
uv run szu-agent                   # 对话；对话中也可以输入 /login
uv run szu-agent logout
```

### 网络要求
- 讲座平台和电费系统**只能在校园网（或学校 VPN）里访问**，请在连着校园网的电脑上运行
- 如果电脑开了 Clash / mihomo 等代理，把 `szu.edu.cn` 和 `192.168.0.0/16` 设为直连（DIRECT），否则学校看到的是代理节点的 IP：内网系统访问不了，统一认证也更容易要求二次验证
- 在云端容器或沙盒里运行时，流量通常从平台出口出去，内网功能必然不可用

### 二次验证
学校对部分系统或“非常用地点”要求二次验证。聊天中会弹出验证卡片（企业微信验证码 / 短信验证码 / 再次输入密码），验证后自动继续。
学校页面上的“信任此设备”依赖浏览器端的设备识别，对本程序无效（实测会被拦回），所以固定按“仅本次登录”提交。

### 排查问题
`uv run szu-agent check sports`：用本机登录凭证对体育预约接口做只读自检，输出只有字段名和项目/场地名称，可以直接贴出来排查。

登录、二次验证、访问学校系统的每一步都会记在 `~/.szu-agent/debug.log`：只有地址、状态码、学校返回的结果码和 Cookie 名字，不含密码、验证码、Cookie 值和学号。

### 单独使用 MCP Server

可以接入任何 MCP 客户端（Claude Desktop、Cursor、Cherry Studio……），配置见 `mcp-config.example.json`。先用上面的命令登录，Server 会自动读取本机凭证。

## 设计要点

### 0. 体育预约：项目目录从学校动态获取
学校预约页的前端脚本（`modules/sportVenue/*.js`）不需要登录就能读到，里面写明了完整流程：
`getSportVenueData.do`（校区/项目目录）→ `getRqList.do`（开放日期）→ `getTimeList.do`（时段）→ `getOpeningRoom.do`（场地）→ `insertVenueBookingInfo.do`（提交）。
所以不写死任何项目编号，学校新增项目也能自动支持；同时支持“包场”和“散场”两种方式。

### 1. 为什么不用浏览器自动化
参考的 szu-cli 用 Playwright 驱动浏览器点击网页。本项目改为直接调用 HTTP 接口：
- 快：一次查询从 5-10 秒（启动浏览器）降到几百毫秒
- 轻：不需要安装浏览器，可以部署到服务器
- 可测：所有学校交互都能用 `httpx.MockTransport` 离线测试

### 2. 登录与凭证
- **扫码优先**：用企业微信扫码，密码完全不经过本程序
- **密码不进 LLM**：登录接口在 Web 后端，不是 MCP 工具。工具参数由 LLM 生成，密码如果成为工具参数就会进入模型上下文和对话历史。测试里会检查“没有任何工具接收密码”
- **密码不落盘**：用学校登录页同样的 AES-CBC 加密后提交，用完即丢；只保存学校颁发的 Cookie（文件权限 600）
- **不破解验证码**：学校要求滑块验证码时直接提示改用扫码
- **跨进程共享**：Web 进程负责登录（写会话文件），MCP 进程调用学校接口（按文件修改时间自动重新加载），所以登录后无需重启
- **单点登录**：各子系统未登录时都会跳转到统一认证；只要凭证有效，统一认证直接签发 ticket 跳回，HTTP 客户端跟随重定向即可自动登录；最终停在登录页就判定为凭证过期

### 3. 写操作的三层防护
1. **工具层**：`*_preview` 只预览，把参数锁定在服务端并签发一次性令牌（10 分钟过期）；`*_confirm` 只接受令牌，LLM 无法在确认时换参数
2. **图层**：路由检测到 `*_confirm` 调用就进入 `human_review` 节点并 `interrupt()`，这是确定性的代码路径，不靠 prompt
3. **展示层**：确认卡片展示的是服务端返回的预览，而不是 LLM 的复述

### 4. 付款：自动化做到“付款前一步”
学校支付页（olepay）用 `X-Frame-Options: SAMEORIGIN` 和 CSP `frame-ancestors 'self'` 禁止被嵌入，查询密码用位置随机的屏幕键盘，
所以付款必须由用户在学校页面上完成，本项目不代付、不接触支付密码。预约成功后弹出付款卡片：
- 显示体育专项经费余额和参考价格（待支付订单金额为 0，用同项目上次实付金额作参考），余额不够时提示选校园卡
- 一个按钮打开学校“我的预约”页去付款
- 每 10 秒查询订单状态，付款成功自动变为“✓ 已支付”，超时被学校取消也会显示

### 4.1 电费充值：同样做到“付款前一步”
学校的充值页（cgdzchat.com “购买电”）下单后返回的是微信 JSAPI 支付参数，只能在微信内置浏览器里调起支付，登录态也来自微信授权，
所以无法在 agent 里付款。agent 弹出充值卡片：剩余电量、日均用电、充 20/50/100 元各能多用几天（电价按抓包算出约 0.70 元/度，
确定性计算，不让模型心算），以及校园卡服务大厅的二维码（已去掉 openid 等个人参数，实测微信扫码可以进入）——在微信里付款。

### 5. 公文通：从“给链接”到“读懂并画出来”
1. `notice_search` 按标题搜索，每条结果按规则自动打标签（申请/报名、公示/结果……；本科生/研究生），并返回分布统计。几百条结果时 agent 先看分布再缩小范围
2. `notice_read_many` 一次读 3-5 篇正文，提取截止日期、金额、条件、材料
3. `show_notice_board`（界面工具，Generative UI）：agent 用 Pydantic 校验过的结构化参数描述面板，前端画成分组卡片 + 截止日期时间线（3 天内标红）。格式不对会被拒绝并让 agent 重试，比让模型写 Markdown 可靠
4. 面板默认只展开最重要的 3 条，其余收进“展开其余 N 条”；截止日期时间线只列最近 3 个
5. 附件：卡片显示出来时才去取附件列表，点击后由本机后端带着登录凭证代为下载（浏览器直接打开学校链接会被要求登录）。
   代下载接口只放行 `www1.szu.edu.cn/board/`，防止被当成访问内网的跳板（SSRF）。
   学校的下载接口要求文件名按 GBK 编码、并带详情页 Referer，否则拒绝或断开连接（实测）
6. 隐私：详情页里学校插入的“（姓名学号 时间浏览）”和导航栏用户名在解析层就被删掉，不会进入模型上下文

### 6. 校园活动发现
公文通按标题关键词（活动 / 社团 / 比赛 / 讲座）检索并去重，加上讲座平台正在报名的讲座。公告只有发布日期，所以 agent 会挑相关的用 `notice_view` 读正文，提取真正的活动时间地点。

### 6.1 图书馆预借：同一套写操作防护，外加“手机号不进模型”
- 流程照抄网页：打开 `addfb.aspx` 拿 ASP.NET 表单 → `addfbcheckAjax.aspx` 预检（0 才能继续，1~7 的含义来自页面 JS）→ 模拟点击 `Button1` 提交 → **提交前后各读一次“我的预借”，这本书多出一条记录才算成功**。最早用的是“再预检返回 1（已预借过）”，真实预借时提交成功了但预检并不返回 1，被误报成“未确认”，于是改成核对记录列表——不依赖任何状态文字或返回码的含义。查不到新记录时报“未确认”且不自动重试，避免重复提交
- 取消：`deletefbAjax.aspx?fid=`（返回 1=成功、0=失败，含义来自页面 JS），只有页面上带取消链接、`status==0` 的记录能取消；取消后再读列表确认
- 测试里有一条不变量：MCP 中所有 `destructiveHint=True` 的工具必须都在 `SENSITIVE_TOOLS` 里，新增写操作忘了接人工确认会直接失败
- 馆藏表不在 `bookinfo.aspx` 的服务器返回里：登录后由页面 JS 请求 `bookinfowithresvAjax.aspx` 再填进去（自检时“有书名、0 册”才发现），所以两个都要请求
- **取书地点在确认卡片上点选**，不在聊天里来回问：预览返回全部选项（用户说了“北馆”之类就预选），卡片上点一个再点确认。点选结果随“确认”交给后端，由图的 `human_review` 节点写进 `library_prebook_confirm` 的参数——模型不需要“听懂”用户选了什么，它自己填的值也会被丢掉；MCP 端再校验必须是预览时页面上真实存在的选项。快递到付不支持（要填收件地址）
- 表单必填手机号。手机号不是工具参数、不进用户画像（画像会渲染进系统提示），只能在网页卡片里填写，存在 `~/.szu-agent/contact.json`（600）；交给模型的预览和确认卡片里只有 `138****8000`，学校邮箱只显示域名（用户名就是学号）
- 测试样例由真实页面脱敏而来：ViewState 换成占位值（它只是 base64，可能含个人信息），预填的邮箱和姓名删掉

### 7. 其他工程细节
- **错误码 → agentHint**：每个错误附一句“该让用户做什么”，LLM 不用理解 HTTP 细节
- **MCP 长连接**：`MultiServerMCPClient.get_tools()` 每次工具调用都新起 Server 进程，确认令牌会丢；这里用 `client.session()` 保持长连接
- **并发写记忆**：模型会在同一步并行调用两次“记住偏好”，加锁 + 原子替换避免互相覆盖
- **礼貌访问**：并发上限 2、只读请求 5 分钟缓存、不自动重试写操作

### 8. 上下文工程：发给模型的不是“全部历史”
代码在 `agent/context.py`，每轮开始时由图里的 `prepare` 节点执行一次。
- **按 token 预算，不按条数**：一条公文通正文可能抵几十条普通消息。用 DeepSeek 官方的换算（中文 0.6、英文 0.3 token/字符）估算，不依赖分词器
- **超预算才压缩，而且一次压一批**：窗口超过 24K token 时，把较早的整轮对话交给 LLM 合并进摘要，只保留最近约 8K。按轮次切，tool_call 和结果不会被拆开。摘要失败不影响本轮回答，由兜底裁剪接住
- **摘要有业务约束**：保留校区、日期、订单号、读过的截止日期；**去掉确认令牌**（一次性、10 分钟过期，模型拿旧令牌去确认只会出错）和个人身份信息
- **为缓存设计前缀**：DeepSeek 对重复前缀自动缓存，命中部分约 1/10 价格。以前系统提示第一段就是“当前时间”，每分钟都变，整段缓存永远命中不了。现在系统提示只放固定指令、画像、摘要（按变化频率排序）；时间改成写在每条用户消息前面，用的是那条消息的发送时间，所以旧消息每次渲染都逐字相同。也因此没有做“每轮把旧工具结果截短”——那样每轮前缀都会变
- **跨天对话的时间问题**：每条消息带自己的发送时间，模型能分清“昨天那条消息里的明天”和“今天说的明天”
- **完整历史不删**：checkpoint 里保留全部消息供界面恢复，压缩只影响发给模型的副本；界面在压缩点显示一条分隔线

### 9. 历史会话
- LangGraph 的 `AsyncSqliteSaver` 持久化图状态，重启后对话、甚至待确认的卡片都还在；另建一张 `threads` 表存标题和时间，列表页不用反序列化所有 checkpoint
- 待确认的操作超过令牌有效期（10 分钟）就不再显示确认卡片，避免用户点了才发现令牌失效
- 隐私：`~/.szu-agent/history.sqlite` 权限 600、目录 700（SQLite 的 WAL 文件会被反复重建，单靠文件权限不够）；默认保留 30 天（`SZU_AGENT_HISTORY_DAYS`，0 为永久）；界面可删除单个会话；演示模式用单独的文件。库里有对话和工具结果，但没有密码和验证码——它们从不进入对话
